# כללי עבודה לפרויקט האתר

הפרויקט נבנה לפי "המדריך המעשי לבניית אתר עם קלוד קוד", שלב אחרי שלב.
סדר העבודה: תיקייה + CLAUDE.md → אפיון (BRIEF.md) → גרסה ראשונה → 10 אפשרויות לכל חלק → תיקונים → בדיקה → GitHub → Vercel → דומיין → גוגל ומדידה.

## כללים קבועים
1. **עברית, מימין לשמאל.** כל עמוד עם `<html lang="he" dir="rtl">`, וכל הטקסטים בעברית אלא אם ביקשו אחרת.
2. **חייב להיראות טוב בטלפון.** בונים מובייל-פירסט ובודקים כל שינוי ברוחב 390px (טלפון), 768px (טאבלט) ו-1440px (מחשב).
3. **חלק אחד בכל פעם, מלמעלה למטה.** לא נוגעים בחלקים אחרים כשעובדים על חלק מסוים.
4. **לא מוחקים ולא מחליפים חלקים שכבר אושרו בלי לשאול קודם.** חלק שאושר = נעול.
5. **אחרי כל שינוי מראים את האתר.** פותחים את האתר בכרום. (בסשן ענן: מצלמים מסך בכרום בטלפון ובמחשב, שולחים את הצילומים, ומפרסמים תצוגה מקדימה כשצריך.)
6. **לא מתקדמים לשלב הבא במדריך לפני שכתבו "ממשיכים".**
7. **נקודת גיבוי (git commit) אחרי כל דבר שאושר,** עם שם ברור. "תחזיר לנקודת הגיבוי X" = חוזרים לקומיט הזה.
8. **אין סודות בקוד.** לא שומרים סיסמאות, טוקנים או מפתחות API בקבצים, ולא מבקשים אותם בצ'אט.

## קבצים חשובים
- `BRIEF.md` – האפיון המאושר. כל החלטה על תוכן ומבנה נבדקת מולו.
- `index.html` – האתר עצמו.
- `options-*.html` – קבצי 10 האפשרויות לכל חלק (לא חלק מהאתר החי).
